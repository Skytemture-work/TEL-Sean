# Turret control

水平／垂直雙軸瞄準控制，給發射機構用。

## 硬體對應（2026-09-24 實測）

| 軸 | 馬達 | ESC_ID | MST_ID |
|---|---|---|---|
| 水平 yaw | 馬達 2 | `0x03` | `0x13` |
| 垂直 pitch | 馬達 1 | `0x01` | `0x00` |

兩顆的 `MST_ID` **不同**，backend 會開機自動讀取，不要改成寫死。

相機**固定在底座**（`camera_on_turret=False`）—— 砲塔轉動不會改變畫面，所以
「是否瞄準完成」必須看馬達回饋，不能看像素誤差。

## ZED 2 相機校正

目前連接的是 ZED 2（序號 `21947470`），程式已填入 HD720 左相機校正值。SDK
`VIEW.LEFT` 預設使用校正後影像：`fx/fy=527.3349`、`cx=651.10596`、
`cy=371.00671`，畸變係數為 0。`run_zed_tensorrt_test` 走這條路徑。

OpenCV 的 `--zed-uvc` 則會從左右並排的原始影像裁切左半邊；`run_board_real`
和 `run_yolo_demo` 會自動切換成此相機原始 HD720 校正：`fx=529.09`、
`fy=528.88`、`cx=646.775`、`cy=363.19`，並套用原廠畸變係數。兩組值不能
互換。若換相機、影像尺寸或裁切方式，必須重新提供對應校正，不能沿用這組值。

## 靶板與接戰順序

3 欄 × 4 列共 12 個孔。**上排 Ø20 cm（小）、下三排 Ø40 cm（大）。**

順序：**大的先** → **逐欄由左到右** → **欄內由下往上**。
水平馬達每欄只移動一次，共 3 次。

```
       欄1        欄2        欄3
上  ⑩ Ø20     ⑪ Ø20     ⑫ Ø20      ← 最後打
    ③ Ø40     ⑥ Ø40     ⑨ Ø40
    ② Ø40     ⑤ Ø40     ⑧ Ø40
下  ① Ø40     ④ Ø40     ⑦ Ø40      ← 從這裡開始
```

### 距離來源

`distance = focal_px × diameter_m / 像素寬度`

正式流程預設使用 ZED SDK，優先利用同一幀的靶面立體深度擬合共同平面，再計算各孔深度。擬合排除孔洞和靶面外點，並以 PnP 姿態檢查一致性；資料不足或不一致時依序退回單孔邊緣深度及 PnP 估距。儀表板會顯示距離來源與平面內點數、殘差。初始孔位偵測也可用上述單目公式估距。
YOLO 若只有一個類別，`classify_by_size()` 會用「大孔是小孔的 2 倍」把兩種尺寸分開；
比例不對時（例如畫面只有一種尺寸）會標成未知，讓開火閘門擋下，而不是亂猜距離。

### 🟢 相機固定在車身 = 三維關節幾何

實機的 `use_axis_geometry=True` 會把每個孔的像素與測距結果轉成相機座標，
再扣除相機到**水平關節**的固定偏移，並換算成水平關節與垂直關節的絕對目標角度。
因此車子停在場上不同位置時，不需要假設靶板在固定像素或固定距離；每一幀會依靶板
目前的距離重新計算角度。`geometry.py` 也會補償水平關節與垂直關節不重合造成的近距離視差。

`run_board_real` 會用靶板 300 × 340 cm 的實際尺寸與至少 4 個非共線孔心做 PnP；完整靶面
四邊形可作為備援，但仍要至少 3 個孔位支持，不能只靠黑色外觀，以免把旁邊鐵架當成靶。
每幀重新投影 H01～H12 並更新距離，但不重建射擊計畫，因此已射球數、
目前索引與計分模式的重複射擊都會保留。車體仍在移動、重投影誤差過大或姿態逾時時，
砲塔可以繼續追瞄，但發射與逾時跳孔都會暫停，直到姿態連續穩定。

競賽計分模式預設啟用（`--no-score-mode` 可切換一般模式），並有短時少孔備援：在最近一次穩定 PnP 後 1 秒內，至少一個可匹配的可見孔可更新平移，單次降級期間最多成功發射一球；若沒有可見孔、匹配不符、更新間隔逾 0.25 秒或運動過快則暫停。此方法沿用原旋轉與深度，單孔無法驗證這些假設，須實地測試。儀表板以 `partial` 標示備援姿態。

螢幕測試的 `--virtual-board` 會自動關閉這段幾何，因為螢幕上的孔徑不代表真實 20/40 cm。

## 模組

| 檔案 | 說明 |
|---|---|
| `config.py` | 所有參數。**大部分仍是暫時值**，見下方 |
| `aiming.py` | 像素 → 角度，含穩定判定與開火閘門 |
| `geometry.py` | 相機座標 → 水平／垂直關節座標與絕對馬達角度 |
| `ballistics.py` | 視差修正 + 重力彈道求解（純數學） |
| `backends.py` | `MockMotorBackend`（安全模擬）與 `DamiaoSerialBackend`（實機） |
| `limits.py` | 馬達座標安全範圍讀寫與最後一道軟體限位 |
| `controller.py` | 接合瞄準與馬達輸出 |
| `control_loop.py` | 200 Hz 固定頻率迴圈 + 偵測執行緒 |
| `board.py` | 靶板模型：測距、尺寸分類、接戰排序 |
| `board_pose.py` | 每幀 PnP 靶面姿態、平滑、移動判定與 12 孔重投影 |
| `dashboard.py` / `dashboard.html` | 區網即時影像、孔位、射擊佇列與砲塔角度儀表板 |
| `engagement.py` | 逐孔接戰驅動，含射擊冷卻與逾時跳過 |
| `detection.py` | YOLO 結果轉靶板目標 |

## 環境限制

⚠ **AGX 的 JetPack R35.4.1 是 Python 3.8.10**，不是 3.9/3.10。

所以**不能直接寫** `tuple[float, float]`、`X | None` 這類語法 —— 型別註解在 def 時就會求值，
會直接 `TypeError: 'type' object is not subscriptable`，連 import 都失敗。

每個檔案開頭都要有：

```python
from __future__ import annotations
```

這在筆電上測不出來（筆電多半是 3.10+），**只有在 AGX 上才會炸**。

`backends.py` 需要 `DM_CAN.py` 和 `dm_port.py`。找不到時會自動去
`../dm_motor_test/` 撈，也可以用 `DamiaoSerialBackend(dm_path=...)` 指定。

## 執行

電腦輸入絕對角度並發射泡棉球，使用新的完整入口：

```bash
python3 -m turret_control.run_precision_fire
# 也可直接指定啟動後的目標角度；仍需輸入 speed、fire 才會旋轉飛輪及發射
python3 -m turret_control.run_precision_fire --yaw 10 --pitch 20
```

啟動時與 `main.py` 共用 DM 初始姿態、MKS 及雙 VESC 初始化。等待提示字元後輸入：

```text
aim 10 20
speed 50
fire
fire
fire
stop
quit
```

`aim 10 20` 為校正後的實體**絕對**水平角 10°、仰角 20°，不是增量角度。
超出校正限位、設定範圍或聯合工作空間時直接拒絕，不會偷偷換成另一個目標。
水平設定範圍為 ±34.5°；`config.py` 的仰角上下限直接引用 `limits.py`，
一般活動範圍統一為 0°～35°，仍與實測機構限位取交集。
仰角超過 30°時，依 `max_activity_pitch_for_yaw_deg()` 隨水平角收窄；
例如水平 10°時仰角上限 33°，仰角 35°時水平必須為 0°。
程式會等待有效回授到位，再接受發射；到位門檻沿用 `main.py` 的 ±2.5° 與低速判定，
顯示小數角度不代表已達到該小數位的實機精度。`status` 可查看目標、回授及階段。
待命時不再定期印出 DM／VESC 遙測，以保持 `precision>` 提示字元可讀；
背景控制與故障檢查仍持續執行，啟動、指令結果及錯誤訊息仍會顯示。

`speed` 使用與 VRB 相同的 0..100 尺度；0 停轉，其餘對應
`VESC_MIN_RPM + speed * VESC_RPM_PER_SPEED_UNIT`（目前 speed=50 為 3000 RPM）。
飛輪初始停轉；設定速度後持續旋轉，直到 `stop`、`speed 0` 或關閉程式。
每次 `fire` 只執行原本的一個 FIRE 階段，完成後才回到提示字元：
第一階段回零後推至 1700 pulses，第二階段再推 1300 pulses，
第三階段沿用原本的回零確認與轉一格流程。回零或轉格失敗即停止，不會自動重試。
三次 `fire` 的機構順序完全沿用 `main.py`，不會額外新增推球行程。

此入口不需要遙控器、不開啟 ESP32 UART，也不送出車輛移動指令。
請先結束 `main.py`／其他馬達控制程式，避免同時占用相同裝置。
`quit`、Ctrl+C、輸入結束或控制器故障時會執行共用關閉流程，停止 VESC／MKS 並讓 DM 回位失能。

`run_manual_move` 在輸入角度並按 Enter 確認後，會共用 `main.py` 的
`VESCDualMotorController` 啟動雙 VESC 串列連線、遙測及背景控制，初始保持停轉。
序列埠與保護設定沿用 `manual.py`；此入口沒有接收遙控器 VRB 速度封包。
VESC 初始化失敗會取消調角；移動或保持期間偵測到 VESC 故障也會停止控制。
按 Ctrl+C 會失能調角馬達並關閉雙 VESC。`main.py` 仍由原本的控制器管理 VESC。

python3 -m turret_control.run_manual_move --pitch 15 --pitch-tau-ff -3.0

# `yaw 30` 向右 30°，`yaw -20` 向左 20°

垂直面板預設使用實機已驗證可移動的 `posvel` 位置－速度模式，外層仍使用加速度限制的
連續軌跡（預設速度 `0.10 rad/s`、加速度 `0.09 rad/s²`），並將命令最大領先實際位置限在 10°，
避免機構落後時累積大量位置誤差後突然跳動。預設 `kp=50`、`kd=1.5`、
重力補償前饋 `0 Nm`（非零值會在使能後 1.5 秒漸增，必須先實機確認方向）；若 2 秒內移動不到 0.25°，
會顯示停滯警告但保留原目標，不再偷偷改成目前位置。終端與面板會同時顯示實際扭矩及
命令－回饋誤差，方便區分控制命令、負載與馬達回饋。每次使能只會先保持當前位置，
必須再輸入一次目標才會移動。

面板輸入的是**物理砲口仰角**，換算式為
`馬達角 = 水平砲口馬達角 + 方向 × 機構比例 × 砲口仰角`。
校正值放在 `startup_pose.json`：水平儀確認的砲口仰角 `0°` 對應馬達約 `+0.221065 rad`、方向為 `-1`、
比例 `1.0` 已由操作人員確認。記錄的 home 馬達位置約 `-0.557908 rad`，按此比例換算約為 `44.63°`；回 home 使用馬達記錄值，不假設精確 `45°`。若日後加入連桿或齒輪，需重新檢查自動瞄準的比例換算，並更新
`motor_rad_per_muzzle_rad`；也可用 `--pitch-sign` 和
`--motor-rad-per-muzzle-rad` 暫時覆寫。砲口仰角安全範圍會由
`mechanism_limits.json` 的馬達端點換算；`--min-angle`／`--max-angle` 只能再縮小，不能放寬。
畫面中的馬達角是編碼器**絕對座標**，正負號不是移動方向；例如砲口從
`+15°` 回到 `0°` 時，垂直馬達目標會增加約 `15°`，砲口則持續向下回到水平。
若在前一個目標尚未到達時改目標，控制器會先按加速度上限煞車，再連續反轉。

同一程序會同時保持水平與垂直兩顆馬達。水平輸入是以目前正前方校正點為 `0°` 的
絕對角度，正值向右、負值向左，限制會由 `mechanism_limits.json` 的水平馬達端點換算（目前暫值為
`-34.5°～+34.5°`）。水平移動前會依起點及目標的最大水平偏角選擇避讓仰角，完成水平移動後再回復目標仰角。`home` 指令先水平置中，再回到已記錄的 home 編碼器位置。

工作區依操作人員實測確認的物理角度換算：仰角 `0°～30°` 水平 `±34.5°`；高於 `30°` 後依三角形從 `±25°` 收窄至 `33°` 的 `±10°`；`33°` 到記錄的 home 為 `±10°` 通道。此多邊形已是確認後的軟體邊界，因此未再額外內縮 `0.5°`；水平 `±34.5°` 相對 `±35°` 機構設計仍保有 `0.5°`。此前的多邊形與原始描邊資料保留在限制檔中。垂直比例 `1:1` 已由操作人員確認。
實機方向校正為 `yaw_sign=-1`：
馬達編碼器角度減少時，砲塔實際向右。

CLI 的 `aim <水平角度> <垂直角度>` 與自動瞄準共用分階段避讓流程，移動中更新的目標會在目前階段完成後重新規劃。
`enable` 與 `disable` 會在輸入後直接執行，不會再要求輸入 `yes`；其中 `disable`
可能讓垂直軸下墜，輸入前仍需先支撐機構。一般的 `set`、`yaw`、`aim` 也都不需要確認。

需要重新量測水平基準時，在 CLI 失能並支撐機構後，使用水平儀調整砲口仰角至 `0°`，輸入 `capture-level` 並確認。此操作保留已記錄的 home 馬達位置及比例；若日後需要更改 home 或工作區，應重新確認機構及更新相應設定，目前沒有自動錄製工具。舊校正檔會備份成 `startup_pose.json.bak`，馬達內部零點不變。
若機械原點有偏差，可在垂直面板 CLI 輸入 `calibrate`，依提示確認兩軸失能、手動放到
「水平 0°、垂直初始 45°」，再輸入 `capture-origin` 並二次確認。這只更新軟體原點，
不改馬達內部零點；舊的 `startup_pose.json` 會備份成 `startup_pose.json.bak`。擷取後維持
失能，必須等人員離開機構才可重新 `enable`。此流程不會重新描繪水平／垂直活動範圍；
本專案目前沒有活動範圍自動擷取工具。

`--board` 模式只開相機與 YOLO，不開 CAN、不建立馬達控制器；必須偵測到 12
個孔且尺寸分類成功，畫面才會顯示 `BOARD READY`。這是接上真機構前的影像流程驗證。

推送到隊友專案後，YOLO 程式預設使用 `robot/best_v2.pt`；舊版
`robot/best.pt` 會保留，不會被覆蓋。也可以用 `--model` 指定其他權重。

靶板孔洞有固定空間 ID：`H01`～`H09` 是三欄由下往上的大孔，`H10`～`H12`
是上排小孔。這個 ID 和接戰順序分開；目前第一個接戰目標是底部的 `H01`，
最後才是上排的 `H10`～`H12`。
`BoardEngagement` 會把 `fired`／`skipped` 事件留在記憶體，若指定 `--log` 則另外
以一行一筆 JSONL 持久保存，包含孔洞 ID、欄列、像素位置、孔徑和距離。

`fired` 代表射擊 callback 回報「球已送出」，不是相機確認球已穿過孔洞；命中確認仍需
另外接射後影像或感測器。

## 不可以拿掉的安全性質

**1. 每一圈都要送馬達命令。** 馬達有通訊丟失防護，停止送命令會自動失能；
垂直軸沒有煞車，失能就直接掉下來。沒有目標時要 `hold()`，不是什麼都不做。

**2. 每個實機位置命令都會在 DAMIAO backend 最後檢查 `mechanism_limits.json`。**
超出各軸範圍或描繪出的 yaw/pitch 多邊形工作區時，目標會停在第一個安全邊界內；這是軟體保護，不能取代急停、機械止擋或人員支撐。

**3. 射擊要有冷卻。** 迴圈 200 Hz，`fire_allowed` 會連續成立 —— 不擋的話一秒射 200 發。
`BoardEngagement` 的 `shot_cooldown_s` 負責這件事，別拿掉。

**4. 開火閘門 fail closed。** 下列任一條成立就不開火：

- 沒有目標或信心度不足
- 馬達還沒到位（看回饋，不是看像素誤差）
- 沒有馬達回饋（無法確認就不開火）
- 目標超出機構角度限位（`clamp()` 夾到限位 ≠ 瞄準完成）
- 目標超出彈道射程
- 需要距離但沒有距離
- 靶面 PnP 無效、已逾時，或車體／相機仍在移動

## 實機瞄準校正與仍需實機確認的參數

這些**必須在真機構上量過才能用**：

| 參數 | 現值 | 要怎麼得到 |
|---|---|---|
| `yaw_zero_rad` / `pitch_zero_rad` | 由 `startup_pose.json` 載入 | 手動校正後於下次啟動自動套用 |
| `yaw_sign` / `pitch_sign` | 1 / −1 | 垂直方向已確認為馬達角增加時砲口下降 |
| `mechanism_limits.json` 的 yaw/pitch 工作區 | 目前是由舊校正推導的保守暫值 | 本專案目前沒有活動範圍描邊工具；限位須依實際量測驗證後再更新 |
| `camera_to_yaw_yaw/pitch_rad` | 0.0 | 炮塔零點時，相機光軸相對水平軸的偏角 |
| `yaw_axis_offset_x/y/z_m` | 0.0 | 量相機原點到水平關節原點，使用相機座標 |
| `pitch_axis_offset_x/y/z_m` | 0.0 | 量水平關節到垂直關節，使用水平零點座標 |
| `muzzle_offset_x/y/z_m` | 0.0 | 舊版彈道補償用：量相機到發射口的距離 |
| `muzzle_speed_m_s` | 20.0 | 實際測球速 |

`run_board_real` 載入 `competition_geometry.py` 的設計尺寸：固定相機仰角 `20°`、
左眼相對旋轉軸向左 `60 mm`、相機中心在軸前方 `101.662 mm`、比水平基準面高
`1.998 mm`；垂直軸在基準面上方 `72.1 mm`。設計 home `45°` 下發射孔相對
垂直軸前 `150 mm`、上 `96.5 mm`，程式會隨仰角旋轉發射孔。實際 home 仍使用
記錄的馬達位置，不設定為設計的 `45°`。模型假設左眼光學中心與圖上的相機中心
同高、同前後位置，需以實機確認。

實機入口目前使用直線出球模型，不套用重力或阻力補償，仍以距離計算幾何視差。
輕球也可能受重力和阻力影響，需在比賽距離實測落點。ZED SDK 預設提供該相機的
校正內參及雙眼深度；UVC 須提供原廠標定檔且沒有雙眼深度。未做實機落點驗證前，
不得把離線幾何測試視為命中精度保證。
